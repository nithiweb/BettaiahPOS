# Bettaiah POS — Offline Android Flutter Application

Independent POS starter with restaurant/retail billing, SQLite local storage, product catalog, inventory tracking, configurable tax, discount, receipt history and JSON backup/restore. **No cloud services, online account or internet required for the installed app.**

## Build an installable APK using GitHub (no Flutter installation needed)
1. Create a **private** GitHub repository named `bettaiah-pos`.
2. Extract this ZIP and upload all files/folders to the repository root, including `.github/workflows/build-apk.yml` (GitHub's web uploader may hide dot-folders; use Git or verify the workflow is present).
3. Go to **Actions → Build offline Android APK → Run workflow**. A push to `main` also starts the build.
4. Wait for the green checkmark, open the workflow run, and download the **Bettaiah-POS-Android-APK** artifact.
5. Unzip the downloaded artifact and transfer `app-release.apk` to your Android device.
6. On the device, permit installation from your trusted file manager and install the APK. Turn that permission off afterward.

The APK is a universal Android build, not split per CPU. Test on your phone, tablet, and POS terminal. Some terminals use custom Android versions or printer SDKs.

## Build locally
Install Flutter and Android Studio, then from this directory:
```bash
flutter create --platforms=android --project-name bettaiah_pos --org com.bettaiah .
flutter pub get
flutter analyze
flutter test
flutter run
flutter build apk --release
```

## Included functionality
- Responsive phone/tablet layout (bottom navigation on phones; navigation rail on wider devices)
- Restaurant/retail mode; select table 1–20 in restaurant mode
- Products and categories, add/edit/archive, optional stock tracking
- Cart, quantities, fixed-amount discount, configurable percentage tax
- Checkout with Cash, UPI, Card or Other **recording only**; no payment gateway
- Transactional SQLite sales and line items; sales history and detail
- Local JSON backup/export and restore using Android share and file picker

## Known limitations
- No KOT, table-held orders, split bills, barcode scanning, hardware printer driver, refund workflow, multi-user accounts, or full GST invoice compliance yet.
- Selecting a restaurant table labels a completed sale; it does not reserve or track open tables.
- Sample products are seeded on first run. Change them before live use.
- This is a starter, not production-certified financial software. Verify tax settings, receipts, data backups and device compatibility before operational use.
- Data is per-device. No cross-device sync; use manual export/import if moving data, and do not use concurrent independent devices expecting shared inventory.
- Restoring backup replaces all data. Keep backup copies in a secure place.
- GitHub Actions release APK is signed with the standard Android debug/release tooling generated for the project; for managed distribution use your own permanent release signing key and configure signing. Do not rely on regenerated keys for future upgrades.

## Security and permissions
The app does not need network access for core billing. Flutter-generated Android manifest may include internet permission in **debug** builds for tooling; the **release** APK should be inspected for its final permissions before deployment. The source contains no cloud endpoints.

## Technical notes
- Flutter SDK pinned in CI to 3.35.7; Android platform scaffolding generated by `flutter create`.
- Packages: `sqflite`, `path`, `path_provider`, `file_picker`, `share_plus`.
- Prices are stored as integer paise to avoid floating-point price storage.
- Checkout uses a SQLite transaction and stock validation.
